# SnapInsight project instructions

Paths in this file are relative to the Git repository root. If starting in a subdirectory, locate the root with `git rev-parse --show-toplevel` before opening these paths.

Read the [project guide](docs/contributing.md), [documentation rules](docs/governance/documentation.md), [workflow rules](docs/governance/workflow.md), and [document index](docs/README.md) before substantive project work. For read-only questions, follow the relevant route in the index. Before implementation, consult current progress and the applicable plan and contracts (FLOW-START, DOC-CURRENT).

Record material changes to requirements, architecture, or contracts before implementation. Use the approved scope or record a proposal for review. Never approve on behalf of the project owner or carry an old approval over to a materially revised contract (DOC-APPROVAL).

Run the applicable checks in the project guide and report actual results and outstanding checks (FLOW-VERIFY). Update progress when starting implementation and record completion, document impact, and verification at delivery (FLOW-CLOSE). Raise conflicts with evidence and continue independent work.
